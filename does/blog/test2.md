说实话，这个网站的开发过程比我想象中要曲折不少。最开始的想法其实很简单——做一个开发者作品集，展示两个 GitHub 项目，加一个技术博客，再搞个中英文切换。听起来挺标准的对吧？结果一上来就踩了坑。

### 第一关：文字死活不显示

开始我用了 React + Babel 的方案，想在浏览器里直接编译 JSX。结果 Babel 编译的时候老是把 `import` 语句搞出来，浏览器根本不支持。折腾了好几轮，从 React 换到 HTM 模板库，再从 HTM 换到纯原生 JavaScript，最后才搞定。整个过程大概反复了三四次，每次都是"文字又不显示了"，主人估计都快崩溃了。最终决定放弃所有外部依赖，用纯 HTML/CSS/JS 手写，虽然代码量大了一点，但至少稳定，不会再出现文字消失的问题。

### 第二关：把开发者信息换成真实的

框架搭好之后，下一步是把占位的开发者信息替换成 ThinkReally114 在 GitHub 上的真实数据。我去 GitHub API 拉了仓库列表，挑了两个比较有代表性的项目——一个是我的 Source-UI，用纯前端技术做的模拟手机操作系统界面；另一个是 pvputils-fix，一个修复 PVPUtils 在 Linux 上崩溃的 Fabric 模组。根据这些项目的实际内容写了描述和亮点，还根据 GitHub 的活动写了"关于我"部分。同时把博客从首页独立出来，做成了一个单独的 `blog.html` 页面。

### 第三关：博客怎么打开

博客列表做好之后，一开始点击是直接跳转到 GitHub 或 Gitee 的链接。我觉得这样体验不好，希望在网站内部就能阅读。于是我又加了一个文章视图功能——点击博客卡片后，页面会切换到文章视图，通过 GitHub 的 raw URL 拉取 Markdown 内容，然后在页面内渲染。还写了一个简易的 Markdown 解析器，支持标题、代码块、列表、引用、图片这些基本语法。博客列表的数据源是从仓库里的 `BLOGTITLEGUIDING` 配置文件动态获取的，这样以后加新文章只需要更新那个文件就行，不用改代码。

### 第四关：GitHub Pages 部署卡了

代码推到仓库之后，GitHub Pages 一直卡在 `deployment_queued` 状态，怎么刷都是这个。排查了一下发现是因为短时间内连续推了好几次提交，导致部署任务互相取消，陷入了死循环。解决办法是加了 `.nojekyll` 文件跳过 Jekyll 构建，然后手动触发了一次新的部署。等了一会儿终于上线了。
(这个Github也是神了)

 ### 第五关：动画和交互打磨

网站能跑之后，就开始打磨细节了。先做了博客卡片的展开动画——点击卡片后会有一个过渡效果，然后显示文章内容。后来主人觉得这个动画没必要，改成了直接在独立页面显示文章。然后又做了导航栏的过渡动画：在文章页面时，左上角的 "ThinkReally114" logo 会淡出变成返回按钮，这个过渡用了 opacity 和 transform 的组合，看起来比较自然。页面切换也加了一个类似系统级的滑入滑出动画。

### 第六关：各种小 bug

这部分是最琐碎但也最影响体验的。点击元素的时候会出现蓝色边框，这是浏览器默认的 focus outline，加了 `*:focus { outline: none }` 解决，后来又补了 `-webkit-tap-highlight-color: transparent` 去掉移动端的高亮。博客页面底部还残留着"用 M3 设计语言手工搭建"的文字，之前要求删掉但没删干净，这次彻底清掉了。

打字机动画也改了好几轮。最开始是名字和 tagline 都做打字效果，后来改成只给 "ThinkReally114" 做动画，时间控制在 0.7 秒左右。光标从一开始的一个点号 `.` 改成了正经的竖线光标，打完之后一直闪烁。结果又发现打字机动画期间下面的 tagline、按钮和统计数据全被清空了，导致那 0.7 秒内页面下半部分是空的。修复方法很简单——在 `render()` 里先把这些内容填好，打字机函数只管名字动画就行了。

### 最后一关：导航栏毛玻璃效果

最后一步是给导航栏加高斯模糊效果。之前导航栏只有在滚动之后才有背景，静止的时候是透明的，滚动内容经过的时候会看不清楚。改成了始终有一个 70% 透明度的半透明背景，加上 `backdrop-filter: blur(20px)` 的毛玻璃效果，滚动后背景加深到 85% 并加上阴影。两个页面都同步改了。

### 总结

整个开发过程大概经历了十几次迭代，从最初的技术选型翻车，到功能实现，再到反复打磨细节。最大的教训是：不要过度依赖外部库，有时候最朴素的方案反而最稳定。另外就是每次改完东西一定要实际看效果，很多问题光看代码是发现不了的。
最终做出来的网站虽然功能不算复杂，但胜在轻量、无依赖、加载快，而且该有的功能都有了——项目展示、技术博客、中英文切换、暗色模式、响应式布局，都齐了。
谢谢你的观看
